Highest byte-diff risk in the plan.

**Files:**
- Modify: goscape's `PixPack` counterpart in `pkg/pack/`
- Test: matching `_test.go`

Three coupled changes:

1. **Crop bounds auto-derived**, not read from `.opt`: scan for pixels that are not magenta (`0xff00ff`); empty image falls back to the full frame.
2. **Pixel order by transition count**, with the return polarity flipped:

```ts
rowTransitions += row !== previousRow ? 1 : 0;
columnTransitions += column !== previousColumn ? 1 : 0;
...

```

Old code summed signed deltas and returned `columnMajorScore < rowMajorScore ? 0 : 1`. Both the metric **and** the polarity changed — getting one right and not the other yields plausible-looking but wrong output.

`memory:int32_hex_literal_overflow` — `0xff00ff` is safe, but the packed `rgb` uses `>>> 0` in TS; mind Go's signedness.
